# 2026-11-09 02:27 旅行ルート記録・手動思い出作成ページ・スポット予測検索と住所リンクの実装

## 1. 変更日時・作業ブランチ
- **変更日時**：2026-11-09 02:27 (JST)
- **作業ブランチ**：`feature/trip-log`

## 2. 背景・目的（Background）
1. **旅行スタート〜旅行終了時の実際の移動ルート記録**：
   - 従来の実装ではピンとピンの間を直線で結んでいるだけだったが、「旅行スタート」押下時に日時と現在位置を取得し、移動した実際のルートを記憶して地図上に線を描画し、「旅行終了」押下で記録をストップする仕組みが求められた。
   - また、レビュー（ピン）を追加した際にルート線がピンの位置へ勝手に引っ張られて追従するのではなく、「ピンの記録」と「通った道のルート保存」を明確に別件として分離する必要があった。
2. **思い出一覧右上の「＋」ボタンからの新規手動作成ページ**：
   - 思い出一覧の右上に「＋」ボタンを配置し、ダイアログ（Picker）ではなく独立した別ページへ遷移して、タイトルと旅行の始まり〜終わりの時間を設定できるようにする。
   - 作成ボタン押下時に、その時間帯にそぐうレビューや写真を自動でまとめ、タイムライン（または記録済みルート履歴）があれば地図上のルート線と思い出内の距離表示（km）に反映させる。
   - Googleマップのタイムラインを貼り付ける方法について、専門用語を使わずクリックすべき場所などを親切にアプリ内で案内する。
3. **スポット検索（予測候補一覧）と住所リンクの改善**：
   - 従来は初期値が東京の住所に固定されており、サンプル以外の店名を打ち込んでもすべて東京扱いになっていた問題を解消する。
   - GoogleMapやInstagramと同様に、店舗名やスポット名を打ち込むと予測候補一覧が表示され、選択したスポットの住所がリンクとして組み込まれるようにする（画面表記はスポット名中心とし、レビュー横の「↗」等にその住所リンクを組み込む）。

## 4. 変更理由・設計判断（Why）
- **案A（GPSリアルタイム軌跡記録＋タイムライン貼り付け対応）の採用**：
  - Googleマップのタイムラインは現在端末ローカル保存仕様であり外部公開APIが存在しないため、旅行中は `geolocator` による実測GPSストリームでルート線を記録し、過去の旅行を手動作成する際はアプリ内履歴またはエクスポートしたタイムラインデータを貼り付けられるハイブリッド構成を採用した。
- **ピンとルート線の分離**：
  - スポットレビュー（点）と移動経路（線）は意味が異なるため、ピン追加時にルート座標へピン位置を混ぜない設計とすることで、純粋に通った道だけを正確に表現できるようにした。
